# 假 flag 与死代码识别

> **所属分类**：Reverse ｜ **难度参考**：中等
> **适用题型**：游戏化外壳（猜数字、闯关）结束时必弹一个"看似正确"的 flag，但提交即错；真正的校验函数被 `jnz` 跳过、正常流程根本不调用。

## 一、知识点原理讲解

### 假 flag（Decoy）

主流程结束时，无论成败都 `printf` 一个格式正确但提交错误的 flag，用来消耗选手时间。识别特征：
- 界面必现、格式工整；
- 一提交就错；
- 它出现的位置在"游戏结束"的公共分支里，而不是"成功"专属分支。

### 死代码（Dead Code）

真正的校验函数在主流程里被一个条件跳转（如 `jnz`）跳过，正常运行永远不执行。它藏着真 flag 的校验逻辑。逆向时要**通读所有函数**，而不是只顺着 main 一路走。判断方法：对可疑字符串/函数看交叉引用，找出"定义了却没人正常调用"的函数。

### 提示串即密钥

字符串窗口里一行英文提示（如 `H0w_t0_3ncrypt?`）常常不是装饰，而是真校验函数里的加密 key。配合一长串 hex 密文一起出现时，基本可以断定加密核心就在引用它们的那个函数里。

### 反转密钥循环 XOR

伪代码形如 `v2 = key[len-1 - i%len] ^ input[i]`，表示**先把 key 反转，再循环取**与输入异或。XOR 自逆，逆运算就是把密文与反转后的 key 逐字节再异或一次。

## 二、通用解题思路 / 套路

```
运行程序 → 结束必弹一个"flag" → 先当干扰，别信
→ DIE 确认无壳 → IDA Shift+F12 全量看字符串
→ 发现孤立的长 hex 串 + 一句英文提示
→ 对二者看交叉引用，定位到同一个函数
→ 检查主流程是否用 jnz 跳过该函数（死代码）
→ 读懂 key[len-1 - i%len] ^ input[i] 结构
→ key 反转后与 hex 密文逐字节 XOR 还原明文
```

易错点：
- `i % len` 与 `len-1 - i%len` 的组合不要漏 `%len`。
- key 要先反转再循环，别直接正序 XOR。
- 界面弹的 flag 一律先当假 flag，真逻辑在死代码里。

## 四、实战例题

### 例题 1：一个猜数字游戏、结束弹假 flag、真校验在死代码里的题

- 题型特征：6 次机会猜 1~100（二分法需 7 次，6 次必不够），用完机会或猜中后程序都打印同一个格式工整的 flag——提交即错，说明界面不是答案。
- 解题思路：Shift+F12 发现一长串 hex 密文与提示串；交叉引用显示二者都指向同一个校验函数；反汇编里主流程用 `jnz` 跳过对该函数的调用，确认是死代码。读懂 `v2 = key[14 - i%15] ^ input[i]`，即把提示串当 key 反转后循环与输入异或，再转 hex 与硬编码密文比较。逆运算：`flag[i] = enc[i] ^ reversed_key[i%15]`。
- 关键工具/脚本：`../assets/images/假flag与死代码识别/xref2.png`（hex 密文与提示串的交叉引用同指一个函数）、`../assets/images/假flag与死代码识别/donotuse.png`（主流程 `jnz` 跳过真校验函数的反汇编）。
- 结果：反转 key 与密文逐字节 XOR，解出真 flag。
