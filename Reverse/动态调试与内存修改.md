# 动态调试与内存修改

> **所属分类**：Reverse ｜ **难度参考**：简单
> **适用题型**：GUI/控制台程序要求"点 N 次、等 N 秒、分数/血量达到超大阈值"才给结果，或静态跟解密链成本过高时，用运行时改内存/寄存器让程序自己走到成功分支。

## 一、知识点原理讲解

### 为什么需要动态调试

有些题静态能看到分支条件（如 `if (count >= 100000)`），但：
- 手动点 10 万次物理上不可能；
- 解密函数的输入依赖运行时状态，硬跟汇编还原加密链成本高。

动态调试的本质：**把程序跑起来，直接读写它的内存/寄存器，把中间变量改成我们想要的值，或直接跳过判断，让程序自己完成后续解密与弹窗。**

### 小端序

32 位整数在 x86 内存里是小端存储。例如十进制 `100000 = 0x186A0`，在内存里的字节顺序是 `A0 86 01 00`，不是 `00 01 86 A0`。改 Hex 时必须按小端写。

### 两类等价做法

1. **改值**：断在比较指令处，把计数器内存改成阈值，让 `cmp` 自然通过。
2. **改跳转**：把条件跳转 `jl/jb` 改成 `nop`（或直接改 EIP 跳到成功分支），让"小于就跳走"不成立。

### Cheat Engine 扫值定位变量

对运行中的进程做"精确数值扫描"：记录界面当前值 → First Scan → 让变量变化（点一次按钮加 1）→ 填新值 Next Scan → 收敛到唯一地址 → 双击加入列表 → 改成目标值 → 回程序再触发一次判断动作。

## 二、通用解题思路 / 套路

```
静态 F5/反汇编找到"中间变量 vs 阈值"的比较指令
→ 记录变量地址/初始值
→ IDA F9 以 Local Windows Debugger 启动（或 CE 附加进程）
→ 在比较处 F2 下断点
→ 触发一次使变量变化的动作，程序断下
→ Hex Dump 跳到变量地址（G 键），按小端改成阈值
   （或把条件跳转 nop 掉）
→ F9 继续，程序走成功分支，弹窗/写文件给出结果
```

易错点：
- 32 位整数小端：`100000` 写 `A0 86 01 00`。
- 断点要下在"比较之后、变量被复用之前"，否则改了也被重新计算覆盖。
- CE 改完值后必须**再触发一次判断动作**（再转一次转盘/再点一次按钮），因为分支是在那次 `cmp` 时才求值；只改值不触发不会弹窗。

## 四、实战例题

### 例题 1：一个"必须点满 10 万次才弹窗"的 GUI 计数器题

- 题型特征：窗口里一个按钮，进度 `x/100000`，点满才弹结果；手动点完不现实。
- 解题思路：IDA F5 找到按钮处理函数里 `if (*ArgList >= 100000)`，计数器在 `.data` 段固定地址。F9 启动程序，在比较处下断点，回 GUI 点一下按钮触发断下；Hex Dump 跳到计数器地址，把 `01 00 00 00` 改成 `A0 86 01 00`（小端 100000），Apply 后 F9 继续，直接弹出结果窗口。
- 关键工具/脚本：`../assets/images/动态调试与内存修改/counter_arglist.png`（.data 段中计数器符号）、`../assets/images/动态调试与内存修改/hexedit_100000.png`（Hex Dump 把计数器改成小端 100000）、`challenge/动态调试与内存修改/counter_demo.exe`（可复现样本）。
- 结果：改值后程序走成功分支，弹窗输出 flag。

### 例题 2：一个"分数达到阈值才解密弹窗"的 GUI 转盘题

- 题型特征：窗口提示"得到 100000 分即给 flag"，静态可见 `if (积分 < 100000) {继续} else {解密 + MessageBoxW}`，但解密函数硬跟成本高。
- 解题思路：不必静态还原解密链。用 CE 附加进程，扫当前积分值定位地址，改成 `100001`，再回程序转一次转盘触发新的 `cmp`，程序自己进入 else 分支完成解密并弹窗。
- 关键工具/脚本：`../assets/images/动态调试与内存修改/ida_pseudocode.png`（静态看到的分数判断与弹窗分支）。
- 结果：改内存分数触发成功分支，弹窗输出 flag。
