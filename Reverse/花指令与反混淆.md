# 花指令与反混淆

> **所属分类**：Reverse ｜ **难度参考**：中等
> **适用题型**：IDA 报 `sp-analysis failed`、函数被截断、F5 无法反编译，`.text` 段反复出现 `call $+5 / add [esp],x / retn` 这类对运行结果无害但破坏反汇编的垃圾指令。

## 一、知识点原理讲解

### 什么是花指令（Junk Code）

花指令是对程序运行结果无影响、但会破坏反汇编/反编译器分析的指令序列。经典三段式：

```asm
call    $+5
add     [esp+1Ch+var_1C], 8
retn
```

执行过程：`call $+5` 把"下一条指令地址"压栈；`add` 把栈上这个返回地址加上 8；`retn` 再 `ret` 到修改后的地址——**实际就是跳回原流，运行时无害**。但它打乱了 IDA 的栈帧平衡分析，导致：
- 函数被提前截断，报 `sp-analysis failed`；
- F5 无法反编译，只能手动读汇编。

### 清除方法：NOP 填充

成套花指令的字节数固定，按长度全部替换为 `nop`（0x90）即可消除干扰：

| 指令 | 字节数 | 替换 |
| --- | --- | --- |
| `call $+5` | 5 | 5 个 nop |
| `add [esp],8` | 4 | 4 个 nop |
| `retn` | 1 | 1 个 nop |

### 关键认知：数据与代码分离

**花指令只污染 `.text` 代码段；真正参与运算的数据数组放在 `.rdata` 数据段，不被花指令影响。** 因此即便代码反编译失败，数组仍可直接从数据段抄出，不必死磕反编译。

### 累积 OR 校验的逆推

遇到 `acc |= cl; return acc == 0` 这类"每轮都必须为 0 才通过"的结构，等价于每轮等式 `arr1[edx] ^ input[pos] ^ arr3[i] == 0`，移项即得明文：`input[pos] = arr1[edx] ^ arr3[i]`。若另有位置置换表 `arr2` 决定第 i 轮算出的字符落在 flag 哪个位置，最后要按 `arr2` 归位。

## 二、通用解题思路 / 套路

```
IDA 报 sp-analysis failed / F5 失败
→ 在 .text 找反复出现的 call $+5 / add [esp],x / retn
→ 按各指令真实字节数，NOP 填充整段花指令
→ 重新让 IDA 分析（或手动读汇编）
→ 识别核心循环：索引运算 + 查表 + 异或 + 累积 OR
→ 三个数组都在 .rdata，直接抄出
→ 按等式移项逆推明文，按位置置换表归位
```

易错点：
- NOP 长度要按指令真实字节数填，填错会错位、后面全部反汇编乱掉。
- 位置置换表决定字符落点，忘了归位会得到乱序串。
- 先确认数据在 `.rdata`，"数据优先、代码后补"，不要死磕反编译。

## 四、实战例题

### 例题 1：一个带花指令、三数组异或 + 位置置换的小程序

- 题型特征：32 位 PE 控制台、体积很小；搜 `flag> ` 提示串交叉引用进主函数，进入校验函数后 F5 失败、报栈帧分析错误。
- 解题思路：识别出成套 `call $+5 / add [esp],8 / retn` 花指令，按 5+4+1 字节 NOP 抹平；手动读核心汇编，看清 `edx=(7*ebx+3)%25`、`pos=arr2[ebx]`、`cl=arr1[edx]^input[pos]^arr3[ebx]`、`acc|=cl`。三个数组（arr1 长度 25、arr2 长度 29、arr3 长度 29）都在 `.rdata` 直接抄出，按 `input[pos]=arr1[(7i+3)%25]^arr3[i]` 逆推，再按 arr2 归位。
- 关键工具/脚本：`script/花指令与反混淆/solve.py`（代入三数组逆推并按位置归位输出结果）。
- 结果：归位后回程序输入打印成功提示，得到 flag。
