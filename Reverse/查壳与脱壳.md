# 查壳与脱壳

> **所属分类**：Reverse
> **适用题型**：拿到一个 PE/ELF 后第一步判断是否加壳、是哪种壳
能否直接静态分析；常见于加壳的 Windows PE 逆向题

## 一、知识点

### 查壳

加壳程序把原始代码/数据压缩或加密后塞进新的节区，运行时先由一段"解压/解包存根（stub）"把原程序在内存里还原，再跳回 OEP（原始入口点）执行
如果不脱壳就直接拖进 IDA，看到的全是解压存根的代码，看不到真实业务逻辑
逆向标准流程的第一步往往是：**先查壳，决定是静态分析还是先脱壳**

### 常见壳与识别特征

| 壳类型 | 识别特征 | 操作 |
| --- | --- | --- |
| UPX | DIE 报 UPX；节名 `UPX0/UPX1/UPX2`；二进制末尾可见 `UPX!` 魔数 | `upx -d` 一键脱 |
| ASPack / PECompact | DIE 报对应名；节名怪异、入口在新节 | 对应专用脱壳脚本或 ESP 定律 dump |
| VMProtect / Themida | 节名常为 `.vmp0/.vmp1`、`Themida`；代码被虚拟化 | 无通用脱壳，多靠动态调试/反虚拟化 |
| 无壳 | DIE 只报编译器不报 packer |  IDA 静态分析 |

### 节名伪装的壳

一种陷阱：**本质是 UPX，但节名被改成 `VMP0/VMP1` 冒充 VMProtect**
`upx -d` 会报错"not packed"，因为 UPX 脱壳时会校验节名是否为 `UPX0/UPX1`
但二进制里仍能搜到 `UPX!` 标记，本质就是 UPX
处理方法：用十六进制编辑器把节表里的节名改回 `UPX0/UPX1`，保存后再 `upx -d` 即可

### PE 节表位置

PE 头里的节表紧随 Optional Header，每个节项 40 字节，开头 8 字节就是节名（ASCII，不足补 0）
改节名只需定位到节表对应偏移，把那 8 字节覆盖掉，不影响其它结构

## 二、通用思路

```
拿到 PE → DIE 查壳
→ 无壳 → 直接 IDA 静态分析
→ 有壳：是 UPX 吗？
   → 节名正常 → upx -d
   → 节名被改（如 VMP0/VMP1）但能搜到 UPX! → 十六进制编辑器改回 UPX0/UPX1 → upx -d
→ 脱壳后再 DIE 验证（应只报编译器）→ IDA 静态分析
```

- `upx -d` 报错时先别放弃，去节表和二进制里搜 `UPX!`，很可能是节名伪装
- 节名是 8 字节定长，改名时不要写超长，多余位置补 `0x00`
- 脱壳后的文件要另存，别覆盖原始样本；脱壳成功的标志是 DIE 不再报 packer

## 三、工具

| 工具 | 安装 | 常用命令 / 参数 | 输出解读 |
| --- | --- | --- | --- | |
| DIE (Detect It Easy) | 官网下载免安装版 | 拖入 PE 即可 | 报 compiler / linker / packer；overlay 区可见 `python3xx.dll`、`PYZ.pyz` 等 |
| UPX | 官网下载 `upx.exe` 加入 PATH | `upx -d xxx.exe`（脱壳）；`upx -l xxx.exe`（列信息） | `-l` 报 packer 名与节信息；`-d` 成功后生成 `xxx.exe` 脱壳副本 |
| 010 Editor / HxD | 官网下载 | 打开 PE → 定位节表 → 改节名字节 | 十六进制编辑，保存后再脱壳 |

命令：

```bash
upx -l target.exe      # 先看是否 UPX、节名是什么
upx -d target.exe      # 节名正常时直接脱
```

## 四、实战

### "假报 VMProtect、实为 UPX"的控制台校验题

- 题型特征：DIE 初看提示某虚拟化壳，但 `upx -d` 直接报错；二进制里却能搜到 `UPX!` 标记
- 解题思路：判断为节名伪装的 UPX
用十六进制编辑器把第一节名 `VMP0` 改回 `UPX0`、第二节名 `VMP1` 改回 `UPX1`，保存后 `upx -d` 脱壳成功；

### 无壳 PE64 控制台程序

- 题型特征：DIE 只报 MSVC 编译器与 Console 链接器，不报任何 packer
- 解题思路：无壳即直接静态分析，无需脱壳步骤，省掉一层
- 这是查壳判断"走哪条路"的典型分支
