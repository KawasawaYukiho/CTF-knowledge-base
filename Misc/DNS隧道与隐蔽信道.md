# DNS 隧道与隐蔽信道

> **所属分类**：Misc ｜ **难度参考**：简单
> **适用题型**：给一份 pcap，其中出现大量异常 DNS 查询，要求还原被 DNS 协议"夹带"外传的数据。

## 一、知识点原理讲解

### 1. 为什么 DNS 能当隐蔽信道

DNS 规定：客户端要访问域名前，必须先向递归 DNS 服务器发查询。而**查询名（QNAME）的内容完全由客户端自定义**。防火墙通常默认放行 53/udp 的 DNS 流量，于是攻击者把要偷出的数据切块、编码后塞进子域名，伪装成正常域名查询发出去，再由自己控制的权威域名服务器"接收"——这就是 **DNS 隧道 / DNS exfiltration**。

### 2. 一眼认出 DNS 隧道

- **子域名异常长且随机**：正常域名是 `www`、`api` 这种短词；隧道流量是一长串无意义大写字母/数字。
- **字符集集中在 `A–Z` 和 `2–7`**：这正是 **Base32 字母表**（Base32 = `A–Z` + `2–7`，共 32 个符号，不含 `0/1/8/9`）。看到只含这些字符的长串，优先怀疑 Base32。
- **固定尾缀**：所有异常查询名尾部都拼同一个域名，那是攻击者控制的 C2 / 接收端域名。**去掉尾缀**，剩下的才是外传数据。
- 数据通常还要补 padding（`=`）再 Base32 解码，之后往往再 zlib/gzip 压缩过，需解压。

## 二、通用解题思路 / 套路

```
拿到 pcap → Wireshark 过滤 dns
  → 正常查询都是短域名，突然出现超长、全大写、只含 A-Z2-7 的子域名段
  → 发现所有异常查询名尾部固定为同一域名（C2 接收端）
  → 去掉 C2 尾缀，把各段子域名去点号首尾相接，拼成一整串
  → 识别字符集为 Base32 → 补齐 padding（8 的倍数）→ b32decode
  → 结果常是乱码 → zlib/gzip 解压 → 还原出明文配置/数据
```

- Base32 长度必须补齐到 **8 的倍数**再解码，否则报错。
- 漏掉 zlib 解压会得到乱码，解压是必查一步。
- 别把 C2 尾缀也拼进数据里。

## 三、工具使用

| 工具 | 安装 | 常用命令 / 参数 | 输出解读 |
| --- | --- | --- | --- |
| Wireshark | 官网 | 过滤 `dns`；看 No. 列里突然变长的 Query Name | 定位异常 DNS 查询与固定尾缀 |
| Python `base64`/`zlib` | 标准库 | `base64.b32decode()` + `zlib.decompress()` | 还原被压缩编码的外传数据 |
| 解题脚本 | — | `script/DNS隧道与隐蔽信道/solve.py` | 自动拼串、补 padding、Base32 解码并 zlib 解压 |

核心代码骨架：

```python
import base64, zlib
b32 = qname.replace(".", "")                    # 去点，把分段子域名拼成整串
b32 += "=" * ((8 - len(b32) % 8) % 8)           # Base32 按 8 补齐 padding
data = zlib.decompress(base64.b32decode(b32))    # 解码 + 解压
print(data.decode())
```

## 四、实战例题

### 例题 1：异常长子域名里的 Base32 隧道，解压还原出配置文件

- 题型特征：pcap 里前几百条都是正常短域名 DNS 查询，从某条包开始出现超长随机大写子域名。
- 解题思路：Wireshark 过滤 `dns`，注意到异常查询名字符集落在 `A–Z2–7`，且每条尾部都固定拼同一个域名（C2 接收端）；去掉尾缀、去点号把各段拼成一整串，按 Base32 补 padding 解码，再 zlib 解压，还原出一段类似 `application.yml` 的配置文本，其中的敏感字段即结果。
