# PNG 结构修复

> **所属分类**：Misc ｜ **难度参考**：中等
> **适用题型**：PNG 打不开、报 CRC 校验错误，或画面被"削掉"一部分；题面提示高度/宽度被改过。

## 一、知识点原理讲解

### PNG 文件结构
PNG 以 8 字节签名开头：`89 50 4E 47 0D 0A 1A 0A`，其后是一串按序排列的 **chunk**。每个 chunk 结构为：

```
长度(4字节,大端) | 类型(4字节,如 IHDR) | 数据(长度字节) | CRC(4字节,大端)
```

第一个 chunk 必为 **IHDR**，其数据 13 字节：

| 字段 | 字节 | 说明 |
| --- | --- | --- |
| 宽度 | 4（大端） | 图像宽 |
| 高度 | 4（大端） | 图像高 |
| 位深 | 1 | bit depth |
| 颜色类型 | 1 | color type |
| 压缩/滤波/隔行 | 各 1 | 其余固定 |

### CRC32 校验
每个 chunk 末尾的 CRC32 覆盖 **`类型字段(4字节) + 该chunk数据`**（不含长度字段本身）。若有人篡改了 IHDR 里的宽/高，CRC 就对不上，图片查看器报 CRC 错误、拒绝显示。

### 修复思路
既然只有宽/高中被改的那 4 字节不确定、其余字段都正确，就**固定其它字段、只爆破宽或高这 4 字节**，使 `crc32('IHDR' + 13字节数据)` 等于文件里记录的 CRC，命中即还原正确尺寸。高度取值通常在 1~数万之间，枚举很快。

### 常见变体
- 高度被改小导致画面被截断（下面内容不显示）；
- 宽度被改；
- 除 IHDR 外其他 chunk 被损坏，思路相同——定位 chunk、按签名/CRC 反推。

## 二、通用解题思路 / 套路

```
PNG 打不开 / 报 CRC 错误
→ 十六进制编辑器定位 89 50 4E 47 后的第一个 chunk
→ 确认类型是 IHDR，读出记录的 CRC32
→ 固定其它字段，只枚举被改的高度(或宽度)4字节
→ 命中 crc32('IHDR'+数据)==记录CRC，写回正确值
→ 另存为新文件，图片正常显示
```

易错点：
- CRC 覆盖范围是 `'IHDR' + 13字节数据`，**不含长度字段**；
- 大小端：宽高都是大端（`>I`）；
- 别把整个文件重下，只需改 IHDR 里那 4 字节。

`script/PNG结构修复/fix_png.py` 核心逻辑：

```python
import struct, zlib
ihdr = data[16:29]                       # 13 字节 IHDR 数据
stored_crc = struct.unpack(">I", data[29:33])[0]
for h in range(1, 0xFFFF):
    cand = ihdr[:4] + struct.pack(">I", h) + ihdr[8:]
    if zlib.crc32(b"IHDR" + cand) & 0xFFFFFFFF == stored_crc:
        # 命中，写回正确高度
```

## 四、实战例题

### 例题 1：CRC 报错的 PNG，提示"高度被剪掉了"
- 题型特征：carving/解压出一个 PNG，打开报 CRC 校验失败、画面被截断；配套另一张图上留了"剪了高度、让 CRC 报错，把它抬回去"的提示。
- 解题思路：在 010Editor 里定位 IHDR chunk，读出记录的 CRC32；运行 `fix_png.py` 固定其它字段只爆破高度 4 字节，命中即写回正确高度，另存后图片正常显示，读出图上文字并按提示做格式变换（如空格转下划线）。
- 关键工具/脚本：`script/PNG结构修复/fix_png.py`（只爆破高度使 CRC32 匹配）、`../assets/images/PNG结构修复/ihdr_hex.png`（IHDR 各字段十六进制位置）、`../assets/images/PNG结构修复/height_clue.jpg`（配套提示图，说明高度被人为剪小）。
- 结果：修复后图上文字按规则变换即为 flag。
