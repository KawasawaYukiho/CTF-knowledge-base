# 日志取证分析

> **所属分类**：Misc
> **适用题型**：给一批 Nginx/Apache 访问日志、错误日志
要求从中还原攻击行为、定位攻击 IP，并把拆散藏在各字段里的结果拼出来

## 一、知识点

### 1. 组合日志（combined log）格式

Web access.log 每行大致结构：

```text
来源IP - - [时间] "请求行" 状态码 响应字节 "Referer" "User-Agent" "Cookie"
```

样例：

```text
10.10.8.60 - - [21/Sep/2026:00:00:00 +0800] "GET /health.php HTTP/1.1" 200 3 "-" "curl/7.88.1" "-"
```

Nginx error.log 样例：

```text
2026/09/21 01:47:12 [error] ... open() ".../wp-login.php" failed ..., client: <攻击IP>, request: "GET /wp-login.php HTTP/1.1"
```

### 2. 取证的核心手法：先降噪，再逐字段还原

- **找异常 IP**：正常用户来自固定内网段（如 `10.10.x.x`）；
某个公网 IP 疯狂扫 `wp-login.php`、`phpmyadmin` 等敏感路径、发注入 payload，就是攻击者
- **URL 编码**：`{` = `%7B`、`}` = `%7D`
- **分片藏匿**：结果不写在一处，而被拆到 Referer、Cookie（如 `last_search=`）、User-Agent、POST body 等不同字段；

## 二、通用思路

```
两个日志文件全局搜 flag / %7B / %7D
  → 在某请求的 Referer 命中结果开头片段（%7B 即 {）
  → 锁定该请求来源的公网攻击 IP
  → 回查 error.log 确认它在扫敏感路径，坐实攻击者
  → 只保留该 IP 的请求，收集碎片
  → body 那段结尾像 == → base64 解码补全尾部
```

- `{}` 被 URL 编码成 `%7B%7D`，搜 `flag{` 会漏
- 分片散在不同字段
- 遇到 `==` 结尾先当 Base64 解

## 三、工具

| 工具 | 安装 | 常用命令 / 参数 | 输出解读 |
| --- | --- | --- | --- |
| Select-String（PowerShell） | 系统自带 | `Select-String -Path access.log -Pattern "flag|%7B|%7D"` | 全局搜结果特征串 |
| grep / findstr | 系统自带 | `grep "<攻击IP>" access.log` | 过滤单个 IP 的全部请求 |
| base64 | 系统自带 | `base64 -d` | 解出 POST body 那段 Base64 |

## 四、实战例题

### 例题 1：从访问/错误日志里拼出拆散在四个字段的结果

- 特征：给一份 Web 访问日志 + 错误日志，要求定位攻击者并还原结果
- 思路：先在两个日志里全局搜 `flag` 和 `%7B/%7D`，在某条请求的 Referer 里命中结果开头（`%7B` 即 `{`）；
锁定该请求来源的公网 IP，回查 error.log 发现它在扫 `wp-login.php`、`phpmyadmin`，确认是攻击者；
只保留这个 IP 的请求，分别从 Referer（开头一段）、Cookie 里 `last_search=` 的值、User-Agent、POST body结尾`==`，Base64 解码
- `Select-String` 日志检索 + `base64 -d`
